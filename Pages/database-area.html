Database structure

A simplified look at the schema behind Logs, our digital archiving & document request system with Role-Based Access Control.

TablePurposeKey fields
usersRegistrar staff and students who can log inid, name, email, role_id
rolesDefines what each account type can access (RBAC)id, role_name, permissions
document_requestsTracks each student's request for a recordid, user_id, document_type, delivery_type, status, requested_date
archived_recordsThe actual digitized student records on fileid, student_id, document_id, uploaded_by, upload_date
02

How the tables connect

Each user is tied to a role, which determines what they can see and do in the system — a registrar staff member and a student see very different dashboards. When a student submits a document request, it's linked back to their account and tracked through its status until it's approved. Once fulfilled, the request points to the matching entry in archived records, which also notes which staff member uploaded it and when — so every digital record stays traceable from request to fulfillment.
